These are developer tools for updating Haskell source rendering. The native CLI
does not execute them, and its users need neither GHC nor these source files.

`SourceTypes.hs` reflects constructor and field names with Template Haskell. It
asks the real `ToData` instances for structural layouts and tags, including
transparent newtypes. It deliberately supports structural encodings only. This
is a built-in codec for `plutus-ledger-api-1.72.0.0`, not a source map for arbitrary
contract types, and is independent of CIP blueprint display titles.

Use a GHC environment with that ledger API, `plutus-tx`, `th-abstraction` and
`aeson` (the Plutus development environment provides these):

```sh
ghc -XImportQualifiedPost -itools -package plutus-ledger-api -package plutus-tx \
  -package th-abstraction -package aeson -outputdir /tmp/cardano-source-types-build \
  -o /tmp/cardano-source-types tools/GenerateSourceTypes.hs
/tmp/cardano-source-types > data/ledger-source-types.json
/tmp/cardano-source-types --fixtures > Tests/Fixtures/ledger-source-values.json
lake build cardano-blaster native-tests
lake exe native-tests unit
lake exe native-tests codecs Tests/Fixtures/ledger-source-values.json /tmp/CardanoSourceCodecs.hs
ghc -package plutus-ledger-api -package plutus-tx -package bytestring \
  -outputdir /tmp/cardano-source-codecs-build -o /tmp/cardano-source-codecs /tmp/CardanoSourceCodecs.hs
/tmp/cardano-source-codecs
```

The fixtures cover all 111 reachable constructor/primitive cases in the V3 type
graph. Their wire values are generated by Haskell. The cross-language check
renders them through Lean, compiles the resulting Haskell expressions and checks
that their actual `toData` values equal the fixture wires. CI exercises rendering
and invalid input rejection without adding a Haskell toolchain to the product.
When changing the pinned ledger model, check the corresponding Haskell package
version and regenerate both files together.
